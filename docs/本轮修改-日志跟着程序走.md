# 本轮修改：日志跟着程序走 + 程序改名 XianyCar+

## 一、日志现在就在程序旁边

**你要的这件事，改起来是对的，我顺手把一处历史包袱也交代清楚了。**

现在的顺序是：

```
① 程序自己所在的目录   ← 首选（就是你要的）
② \iNAND
③ \Residentflash2
④ \SDMEM
⑤ \
⑥ \Windows
```

也就是：**你把 XianyCar+.exe 放哪个文件夹，carlife-log.txt 就生成在同一个文件夹里。**
拷 U 盘的时候顺手一起带走，不用再进车机里翻 iNAND 了。

程序启动时屏幕上会把这行显示出来（现在能看清中文了）：

```
日志：\carlife-log.txt          ← 就是程序旁边那个
```

只有在**程序所在目录写不进去**时（比如被放进了只读区），才会按上面的顺序往后退。
选到哪个目录，屏幕上和日志头上都会写明白。

### 顺便交代一下：那个「U 盘写日志会崩」的历史包袱

代码里原来有一段注释，说早期实测过「程序放 U 盘 + 日志写 U 盘 → 第 4 次 WriteFile 就卡死，
日志永远只有 3 行」，所以当时把 U 盘排到了最后。

**那次的真因不是 U 盘，是当时日志写在【主线程】上** —— 写盘一卡，窗口就永远建不出来，
用户看到的是「点了完全没反应」。这个根因早就修掉了：
现在日志**完全跑在后台线程里，主线程一个字节都不碰文件**。

再加上写之前会先用 `dir_writable()` 真写一个探针文件确认可写，
所以把「程序所在目录」放第一位是安全的。

> 万一现场真的出现「日志写不进去/写一半断了」，
> 屏幕上会提示，日志的写入失败次数也会带回来 —— 那时候我们再退回 iNAND 也行。
