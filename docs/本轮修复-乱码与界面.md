# 本轮修复：屏幕乱码 / 看不见握手进度 / 品牌名

## 一、乱码 —— 确实是我代码里的 bug，根因找到了

你说的那一幕：

> 「试了 6 个设备名都打不开 就没显示出来 而是显示了一堆乱码」

错在 `a2w_ui()` 这个函数。它原来写的是：

```c
w[i] = (WCHAR)(unsigned char)a[i];     /* 一个字节换一个宽字符 */
```

也就是**它根本不认识 UTF-8**。而本程序里所有从日志、协议、RSA 那边来的字符串
**全是 UTF-8**（汉字一个字 3 个字节）。于是：

```
"打不开任何 ADB 设备"     ← 实际在内存里是 24 个字节
   ↓ 逐字节强转
"æ‰"ä¸å¼€ä»»ä½•" ADB è®¾å¤‡"   ← 屏幕上就变成这么一长串看不懂的东西
```

**汉字越多，屏幕上的乱码越长** —— 所以「六个设备名」那行最惨，它正好全是汉字。

现在改成了**真正的 UTF-8 解码**（1/2/3/4 字节全支持，解不出来的才换成 `?`），
并且把代码里**另外 5 处同样的逐字节强转也一并换掉了**：
H.264 解码器日志、两条失败原因、日志路径、拉起手机端的说明。
现在这些位置应该都是正常中文了。

### 顺带修掉一个更要紧的：日志里的「屏幕 |」那一行也全是问号

`w2a_log()` 原来把**所有非 ASCII 直接换成 `?`**，所以日志里：

```
[5.258] 屏幕 | ??????? 4 ?????????????????? ADB ??????????????????
```

这一行本来是「屏幕上当时到底显示了什么」的**唯一记录** ——
你拍屏幕 + 带日志两条线索是用来互相印证的，中文一没，这条路就断了。
现在它输出真正的 UTF-8，日志里那行会和你屏幕上看到的一字不差。

## 二、握手成功了屏幕上却没反应 —— 也修了

> 「日志里显示握手成功了 但是我在程序页面上也没见显示认到手机呢？
>   我只有看了日志我才知道有链接成功过...」

这条批评完全成立。原因是：**握手过程只写了日志，没有任何一处去更新界面**。
（另外上一次那个 `_vsnprintf` 崩在了同步成功状态的那一句上，所以更看不到。）

现在把握手的每一步**同时接到屏幕上**：

| 握手走到哪 | 屏幕上显示 |
|---|---|
| 刚发出 CNXN | 已认到 USB 设备，正在和手机握手 … |
| 手机回了 AUTH | 手机已应答，正在做 ADB 认证 … |
| **我们发了公钥** | **⚠ 请看手机：会弹「允许 USB 调试」，勾「一律允许」再点「允许」** |
| 收到 CNXN | **✅ 已认到手机（ADB 握手成功），正在建数据通道 …** |
| 中途失败 | 握手中断，稍后自动重试（细节见日志） |

其中**「发了公钥」那一条最重要** —— 那一刻手机马上要弹框，
以前用户根本不知道该去看手机；现在屏幕上会直接喊他去看。
