# 车机现场测试指南

> 一趟车机很费事，这份指南的目标是：**一次问全所有问题，不白跑。**
> 按顺序做，每一步都告诉你要看什么、把什么发回给我。

---

## 一、出门前：把三个程序拷到 U 盘

编译完成后，从 GitHub 的 Actions 产物里下载 `wince-exe`，解压后应有三个文件：

| 文件 | 作用 | 优先级 |
|---|---|---|
| `WinCE-NetProbe.exe` | **网络 + 解码器 + 握手 全探测** | ⭐ 先跑这个 |
| `WinCE-CarLifeHU.exe` | 只读屏幕信息（分辨率/色深） | 顺带跑 |
| `WinCE-CarLifeClient.exe` | 协议客户端：握手→视频初始化→收帧取证（含 `video-dump.bin`） | 再跑 |
| **`WinCE-CarLifeView.exe`** | ⭐ **最终程序：显示手机画面 + 触屏回传** | **最后跑，这才是成品** |

**拷到 U 盘根目录即可**（车机文件管理器好找）。

---

## 二、到车上：关键一步 —— 把程序放进亿连的文件夹

⚠️ **这一步不能省。**

亿连自带的硬件解码器（`TCC89X_VDEC.dll`、`VDEC_785.dll` 等）**只在同一个目录下才找得到**。
如果程序放在别处，探测结果会显示「无」，我就无法判断车机到底有没有硬解能力。

**做法**：在车机文件管理器里找到原来装亿连（EasyConnected）的那个文件夹，
把这三个 exe **复制进去**，然后从那个文件夹里运行。

> 找不到也没关系 —— 那就先随便找个地方跑一遍，把结果发我，
> 我根据结果再告诉你要不要挪。

---

## 三、手机上要做的准备（顺序很重要）

1. **先插线之前**，在手机上打开 **Jovi InCar**，让它进入"等待连接"状态
2. 开启 **USB 网络共享**（设置 → 个人热点 → USB 共享网络）
   - 如果找不到这个开关，说明手机型号/系统不支持，直接告诉我
3. 用数据线把手机插到车机的 USB 口
4. 手机若弹「是否允许访问设备数据」之类的提示，**选允许**

> 💡 我们走的是「无线协议 + USB 网络」这条路 —— 也就是
> **把手机的网络共享给车机，然后车机通过网络连手机的 CarLife 服务**。
> 这样就不需要开发 ADB 主机，能省掉最大一块工作量。

---

## 四、按顺序跑，每一步拍照

### 第 1 步：跑 `WinCE-NetProbe.exe`

它会依次报告：

| 报告项 | 含义 | 我要用它判断什么 |
|---|---|---|
| `[OK] WSAStartup 成功` | ws2.dll 可用 | 网络能力基础是否具备 |
| `[OK] 拿到 N 个 IP` | **车机拿到网络了** | ⭐ **M2a 成败的关键** |
| `[X] 没拿到任何 IP` | 车机没网络 | 得转 ADB 方案（工作量大得多） |
| `候选地址...: 通了` | 手机的服务端口可达 | 协议层能开工 |
| `matchStatus=N` | **握手成功** | ⭐ **手机认不认我们的程序** |
| 解码器 DLL 列表 | `[有]`/`[无]` | 视频怎么解码 |

**📸 拍下窗口内容。**

> 💡 **两个贴心设计**
> 1. **结果超出屏幕时，点一下屏幕就翻到下一页**（点到底了再点一下才关闭窗口）
> 2. **结果会自动写成文本文件**，就在程序所在目录：
>    - `netprobe-result.txt`
>    - `client-result.txt`
>
>    **把这两个 txt 拷到 U 盘、传回手机发给我**，比拍照清楚得多。
>
> 3. **客户端还会存一个 `video-dump.bin`**（最多 2MB）
>    —— 这是**收到的手机画面原始数据**。
>    **⭐ 这个文件最重要**：我拿到它就能在本机离线分析出真实编码格式和帧结构，
>    **不用再跑第二趟车机**。请务必一起拷回来。
>    （文件是 UTF-16 格式，电脑记事本能正常打开；手机上如果打不开就拍照也行）

### 第 2 步：跑 `WinCE-CarLifeHU.exe`

只显示屏幕分辨率和系统信息。
**📸 拍照** —— 我需要知道车机屏幕的确切分辨率，才能定视频参数。

### 第 3 步：跑 `WinCE-CarLifeClient.exe`

它会走完整流程并报告：

- `[OK] 找到 x.x.x.x:7240` —— 找到手机
- `[OK] 手机回复 msgId=0x10002` —— 握手成功
- `手机采用 768x480 @30帧` —— 手机实际用的参数
- `首帧头部: xx xx xx ...` —— ⭐ **决定编码格式**
- `格式判断: JPEG` 还是 `H.264`
- `共 N 帧，合计 M 字节` —— 是否真的在推流

**📸 拍照。**

---

### 第 4 步：跑 `WinCE-CarLifeView.exe`（最终程序）

**这才是成品** —— 它会尝试把手机画面显示出来，并且车机屏幕按下去能操控手机。

- 满屏显示手机画面，**底部有一条深色状态栏**，从左到右是：
  - **状态文字**：帧数 / 解码数 / 显示数 / 帧率（如 `120 帧  解码 118  显示 118  约 14 帧/秒`）
  - **蓝色按钮**：当前请求的画面参数，如 `480x272@15`。**点它切换下一个预设**
  - **绿色按钮**：触摸包头长度，`触包8` / `触包12`。**点它切换**
  - **红色按钮**：`退出`

### 这两个按钮是干什么的（现场要试）

**蓝色（分辨率）** —— 老车机软解 JPEG 有性能上限。默认是 `480x272@15`（每秒 200 万像素），
因为 `768x480@30`（每秒 1100 万像素）几乎不可能做到。

**点它会在 5 个预设里循环**，从省到费：

```
320x240@10  →  400x240@12  →  480x272@15  →  640x360@20  →  768x480@30
```

- **卡顿就往前点**（往小的方向），**流畅就往后点**（往清晰的方向）
- 选择会存进 `viewer-res.txt`，重启程序也记得
- 找到「最清晰且不卡」的那个，**把名字告诉我**

**绿色（触摸包）** —— 触摸消息的包头是 8 字节还是 12 字节，这是**唯一一个我只能推断、
没能实证的点**。如果点了屏幕手机没反应，就**点一下这个绿按钮换成另一个再试**。

> 其他厂家实现里 `TOUCH` 走的是 CTRL 通道（8 字节），所以默认 8。但没在真机上验过。
- **点画面就是点手机** —— 触摸会按比例换算回传到手机
- 如果手机推的不是 JPEG，状态栏会**明说**「手机推的是 H.264，不是 JPEG，本程序还不能显示」
  （不会假装在显示误导你）

**📸 不管成功失败都拍照。** 成功的话，**再拍一段车机屏幕被手机操控的视频**。

## 五、如果某一步失败，怎么告诉我

**不用自己分析，把看到的东西原样发我即可**，包含：

1. 哪一步失败的（第 1/2/3 步）
2. 窗口上的**完整文字**（拍照）
3. 手机当时的界面状态（拍照）
4. 车机品牌型号（如果你知道）

如果窗口是空白的或者一闪就没了，也告诉我 —— 那说明程序没跑起来，
可能是我编译出的 PE 有问题，我会据此调整。

## 六、各种结果分别意味着什么（给你个底）

| 结果 | 意味着 |
|---|---|
| 拿到 IP + 握手成功 | 🎉 **最难的一关过了**，剩下是解码和显示，属于工程量问题 |
| 拿到 IP 但端口不通 | 手机 CarLife 没在网络上监听，需要换个手机设置方式试试 |
| 拿不到 IP | 车机没有 USB 网络共享主机驱动 → 转 ADB 方案（要自己实现 ADB 主机，工作量大） |
| 程序根本跑不起来 | 我编的 PE 有问题，我改完再来 |

## 八、最省事的做法

如果嫌拍照麻烦，**只拷那两个 txt 文件给我就够了**：

- `netprobe-result.txt` ← 最重要（网络与握手结论）
- `client-result.txt` ← 帧序列表
- **`video-dump.bin`** ← **最有价值**（真实画面数据，最多 2MB）

前两个不到 5KB，第三个最多 2MB，微信/QQ 发文件都没问题。

**如果只能带回来一个文件，就带 `video-dump.bin`。**

拿到后我会用本机脚本立刻分析出来：

```bash
python3 scripts/analyze_dump.py video-dump.bin client-result.txt
# → 判定 JPEG 还是 H.264
# → 若是 H.264，直接从 SPS 解出真实分辨率/档次
# → 帧大小分布，看有没有超大帧会撞缓冲上限
```

> 这个脚本已用合成数据自测通过：JPEG 能读出尺寸与类型，
> H.264 能从 SPS 准确解析出 `768x480 profile=66(Baseline)`。
