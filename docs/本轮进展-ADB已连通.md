# 本轮进展：ADB 已经打通了（这是最难的一关）

## 一句话

你这趟带回来的日志里，**车机和手机之间的 ADB 认证已经成功完成**：

```
[17.313] ADB 设备已打开: ADB1:
[17.469]    [握手] 已发 CNXN，等手机应答
[17.473]    [握手] 收到包  (0x48545541, 0x14)        ← AUTH，20 字节
...
[30.544] ADB 设备已打开: ADB1:
[33.289]    [握手] 收到包  (0x4e584e43, 0x179)      ← CNXN！手机认了我们的钥匙
[33.289]    [握手] 握手完成 maxdata  (0x40000, 0x0)
```

`0x4e584e43` 就是 "CNXN" 四个字母 —— **手机接受了我们发过去的公钥，连接正式建立。**

从「车机上有台 ADB 主机」到「手机同意被这台车机调试」，中间的所有协议细节
（CNXN / AUTH token / RSA-SHA1 签名 / 发送公钥 / 等待用户点「允许」）**全部走通了**。

## 更值得说的是：上一版那个 bug 的修复，被日志直接证实了

对比两版日志，同一时刻的表现完全不同：

| | 上一版 | 这一版 |
|---|---|---|
| 打开 ADB1: 之后 | 14 毫秒就报「认证失败」，**自己把自己判死** | 发完 CNXN 后**老老实实等到了应答** |

上一版之所以 14 毫秒就放弃，是因为把驱动「此刻还没数据」当成了「设备坏了」。
这一版改成在超时预算内继续等之后，**第一次尝试就等到了手机回的 AUTH 包**，
中间只隔了 4 毫秒。

> 也就是说：这个 bug 是真的，修法也是对的。**要是没修，手机设置得再对也永远连不上。**

## 另外两件从日志里读出来的事

**① 手机上「USB 调试」确实打开了，而且你点了「允许」。**
第一轮（17~19 秒）流程是这样的：

```
收到 AUTH token（第 1 次）→ 我们发签名 → 手机：不认识这把钥匙，再给一个 token
收到 AUTH token（第 2 次）→ 我们发公钥    → 手机弹「允许 USB 调试？」→ 连接被踢掉（正常）
```

**这个「踢掉」是安卓的正常行为**：收到新钥匙后它会断开一次，等你点允许再把钥匙存下来。
之后第二轮（30~33 秒）再连，直接把钥匙一递 —— **手机立刻回了 CNXN，没有再弹框**。
说明第一轮那次你已经点过「允许」了。

**② 设备句柄「脏」的判断也是对的。**

```
[19.995] 读设备失败
[24.529] CNXN 写设备失败      ← 旧句柄已经死了
[28.538] 设备句柄重开（连续失败 4 次）
[30.544] ADB 设备已打开: ADB1:  ← 重开后立刻就好
```

如果不重开，我们会一直拿着一个已经失效的句柄空转，一直到这一轮结束。

## 但日志在「握手完成」那一行就断了 —— 这是这次要修的

```
[33.289]    [握手] 收到包  (0x4e584e43, 0x179)
[33.289]    [握手] 握手完成 maxdata  (0x40000, 0x0)
（后面一个字都没有）
```

握手成功之后，紧接着要跑的代码是：

```
③ 建 3 个本地监听端口（7240 / 8240 / 9340 的转发落点）
④ 起转发线程
   设好状态文字「已连接手机，3 条端口转发就绪」
```

日志一句都没留下，说明**程序就停在这一小段里**。

### 嫌疑犯只有一个：`_vsnprintf`

我把整个工程的导入表数了一遍：**`_vsnprintf` 全程序只被一个地方引用** ——
就是那句「已连接手机，N 条端口转发就绪」用的格式化函数。而它：

- 是握手成功后**第一个**会被调用、且**以前从来没在你这台车机上跑过**的东西；
- 握手之前的所有日志走的是 `cl_log` 自己手写的格式化（那套已经在车上跑过成千上万次）；
- `cllog.c` 当年就是因为同一家族的函数在车上崩过，换成手写格式化之后日志才正常。

所以这一版把它**彻底删掉了**，换成同样手写的 40 行（只支持 `%s %d %u %x`，
本项目用到的全在这里）。现在再从导入表看，`_vsnprintf` **已经不在程序里了**。

### 顺手还拆掉一颗地雷

审代码时发现 `close_conn()` 里少了一对大括号，导致**对自己没持有的临界区调用
`LeaveCriticalSection`** —— 这会把 WinCE 的锁状态搞乱，让两个线程同时进锁、
写坏 ADB 通道表。表象会是「数据莫名少了 / 通道莫名关了」，极难查。
现在改成整个函数体在锁里。

## 下一趟的目标（已经往前挪了一大截）

上一趟的目标是「让车机认出手机」——**达成了**。
这一趟的目标是：

1. 看日志里 `[转发] …` 那一串能走到哪一步（现在有 8 个检查点了）；
2. 如果走到了 `[转发线程] 已启动`，接下来就是**把手机端的智能车载拉起来**
   （车机会通过 ADB 执行 `am start`），然后连手机的 7240 端口；
3. 手机上如果弹出权限框（比如「允许 Jovi InCar 投屏」之类），点允许。

屏幕上看到 **「正在启动车载系统」** 就说明已经过了 ADB 这一关。
