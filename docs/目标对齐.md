## 一、一句话目标

在 **WinCE 6.0 车机**上写一个自研程序，通过 **USB** 连接 **vivo 手机**，
让手机上的 **Jovi InCar 车机系统**直接显示在车机屏幕上，并用车机的**触摸屏**操作它。
**全程不需要任何硬件盒子。**

## 二、你视角的完整流程（做成了是什么样）

1. 手机 USB 线插到车机 USB 口
2. 车机上打开我写的那个 exe
3. 手机弹授权提示，点"允许"
4. 车机屏幕出现 **Jovi InCar 的车机界面**（导航/音乐/电话那一套图标网格）
5. 点车机屏幕上的导航 → 手机上高德启动 → 车机屏幕显示导航画面
6. 声音从车机喇叭出来

## 三、硬约束

| # | 约束 | 来源 |
|---|---|---|

| 6 | 手机上要连的是 **Jovi InCar 车机系统**，不是简单投屏 | 你说的 |

## 四、我理解的技术路线

- 手机侧的 Jovi InCar **内含百度 CarLife 组件**（vivo 官方 FAQ 证实）→
  所以车机端只要**实现 CarLife 车机端协议**，手机就会把它当成车机认下来
- 传输：**USB 有线**（车机没有 Wi-Fi）
- 车机端需要实现：CarLife 协议 + H.264 视频解码 + DirectDraw 显示 + 触摸回传 + 音频

## 五、我理解"不做"的事

- ❌ 不做手机屏幕原样镜像（那是投屏，不是你要的车机系统）
- ❌ 不买/不用转接盒
- ❌ 不改手机（不刷机、不 root）
- ❌ 不改车机系统（不动固件）

## 七、我已知的风险（先说清楚，不藏）

| 风险 | 说明 | 影响 |
|---|---|---|
| R1 | CarLife 的 **USB 传输方式还没确定**（ADB / AOA / USB 网络） | 决定最难那块的工作量 |
| R2 | **H.264 软解在 WinCE ARM 上可能很卡**；车机硬解库还没确认 | 可能不流畅 |
| R3 | 开源 CarLife 协议实现是**旧版本**，手机里装的是 CarLife 8.7.1 | 可能要适配 |
| R4 | 整体工作量 **3–6 个月**（一切顺利的话） | 时间成本 |
| R5 | 做完也可能因为 R1/R2 **走不通**，那时只能换方案（比如自制投屏） | 项目级风险 |
